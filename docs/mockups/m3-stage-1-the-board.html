The Records Board

Milestone 3 Stage 1 mockups — the records board becomes the landing screen at /, with the engine underneath it (PRD criteria 175–196). Matches docs/DESIGN-SYSTEM.md's existing Kitchen Table language exactly: same tokens, no new colours, nothing reinvented except the two components this stage genuinely needs. Purple dashed boxes are designer annotations, not app UI. Player names are the standard mockup set, Player A–E.

Design decisions to approve

  1. The board's AppBar carries the wordmark, not a page title — "Five Crowns Ledger", no context line, no back arrow. It's the one screen with nowhere to go "back" from, the same reasoning already applied to the global error screen.
  2. One archive-statement line sits at the very top of the body, in a plain neutral box (never a semantic warn/error colour — it's a fact, not a problem). Under 10 games it's criterion 183's line verbatim; at 10+ it's replaced outright by a plain count, never a reworded version of the caveat — this is two different sentences, not one restyled.
  3. "Games" and "Add a game" sit directly under that line, as a fixed pair of equal-height buttons, in every state including the empty archive — the same "always reachable, even against nothing" precedent IndexNav already set on the games list.
  4. RecordCard is deliberately flat. No crowns, no medal colours, no 1st/2nd/3rd styling, no ranking of the records against each other — five independent facts in a plain list, each one large tap target to its drill-through with a small chevron as the only affordance. Joint holders are listed alphabetically on one line, each with their own sample count.
  5. The stalwart is the one card that doesn't repeat itself. Its number is the holder's own game count — "from N games" would just print the same figure twice — so that card shows one number, captioned "games played," and nothing else. Flagged for explicit sign-off below; every other card keeps the full sample sentence.
  6. A no-holder row is a plain card, not a warning. Same shape as every other record, no chevron (there's nothing to drill into), the fixed sentence in muted italic where the number would sit. Demonstrated here against a Stage 2 record ("the drought") since none of Stage 1's five can actually go holderless over a non-empty archive — see the note where it appears.
  7. Drill-through reuses GameRow exactly, under a heading that states the claim. "Most rounds won" adds one small line per row — that player's own tally in that specific game — because the claim is a running count, not a single fact each game either has or doesn't. Flagged below: streak drill-throughs are ordered oldest→newest rather than the usual newest-first, since a run reads as a run in the order it happened.

The board — early days (3 games)

Criteria 179–185, 196. Under EARLY_DAYS_BELOW = 10, the fixed line sits once at the top and doubles as criterion 182's archive statement. "Most wins in a row" is a true joint record at 1 each — shown plainly, no footnote. "Lowest average score" is the founder's own example almost verbatim: a one-game player holding a record, honest about it.

Story behind the numbers: Player A won games 1 and 3 (2 wins, sole). Player B won game 2. Neither ever won twice in a row — game 2 broke Player A's run — so the longest recorded streak on this whole board is 1, jointly held. Player E played exactly one game and had a very good night in it. Player C never won a game here but took the most individual hands — the board is allowed to disagree with itself; nothing reconciles the two.

The board — past 10 games (23 games)

Criteria 182–183. The early-days line is gone entirely — not reworded — replaced by a plain one-line count that still satisfies criterion 182 on its own. Records read cleanly at a healthy sample; "most wins" still shows a joint holder to prove that isn't only an early-days thing, with two very different sample sizes side by side (Player E joined the group partway through).

The board — desktop (1280px)

Hard rule: every screen works at 375px and 1280px. Records move to a two-column grid past a comfortable reading width; nothing about a card's content changes, only the layout around it. The nav row and archive line stay full-width and centred with the grid, capped at --container-wide.

Drill-through — "Most rounds won"

Criterion 186: tapping a record lands on exactly the games it was computed from, newest first, in GameRow format, under a heading stating the claim. This is Player C's card from the early-days board — nine rounds across three games, never the game's actual winner in any of them.

Empty archive

Criterion 191: not an error, not a board of zeros. "Games" and "Add a game" stay reachable even here — the same "always rendered" precedent IndexNav already set.
